3daysインターン プロンプト集

「コピー」を押して、いつものチャットAIに貼ってください。一字一句そのままでなくてOKです。

4つのコツ（会話の途中で足す）

暗記しなくてよい。全部使わなくてよい。会話の途中で、足りない一段だけ足す。

1.開始（タスクと条件）
これまでの議論を下に貼った。

タスク: 困りごとを「誰の／どんな困りか」の1文にして。
条件: 新しい事業アイデアは出さない。改善案もまだ出さない。

これまでの議論:
（ここにメモや発言を貼る）
2.対話を続ける
最初の答えはたたき台として使う。やり直さなくてよい。
誰が・どの場面か、まだ広い。そこだけ具体にして。
3.見本を見せる

見本の一文は、自分たちの議論に合わせて差し替えてよい。

欲しい形の見本:「放課後のお迎えで、支援級の保護者が先生と3分も話せない」
この短さと粒度で、他の困りも1文ずつ。
4.分解して伝える（今の一段）
1文はこれで十分。今の一段だけやって:
まだ話していない切り口を4つ出して。
近いものを1つ推すのは次。改善案はその次。
5.5つのレシピの空欄

全部埋めなくてよい。口頭の主は タスク と 条件。

役割: （必要なときだけ）
タスク:
背景: （これまでの議論を貼る）
条件:
出力形式:

① 思考を拡げる

今ほしい一段だけ。全部使わなくてよい。太字が投影と同じ本丸。 その下は、同じ趣旨で一段足すとき用。

A. 切り口を広げる

視点を広げる。まだ話していない切り口を出す。事業アイデアは出さない。

6.切り口を広げる（①-A）【投影と同じ】
これまでの議論:
（ここにメモや発言を貼る）

お願い:
1. 出てきた困りごとを、「誰の、どんな困りか」の1文に書き換えて
2. まだ話していない切り口を4つ出して
3. どれが今日の議論と一番近いか、根拠つきで1つ推して
ただし、新しい事業アイデアはまだ出さないで
7.視点を変える

同じ困りを、賛成と反対から見る。似た切り口ばかりのときに。

この課題仮説について、賛成側と反対側、それぞれの視点から1文ずつ。
事業アイデアは出さないで。
8.立場を変える

役割は、自分たちの議論に合わせて差し替えてよい。

この困りを、「役割A」の視点と「役割B」の視点、2つの立場から1文ずつ。
例: 保護者と先生、本人と家族。事業アイデアは出さないで。
9.漏れとダブりを見る

切り口を出したあと。近いものはまとめる。

今出した切り口は、モレなくダブりなくなっているか確認して。
漏れがあれば指摘して、1つ補って。事業アイデアは出さないで。
10.一段深く聞く

1文はできたが、まだ薄いとき。

今の困りについて、重要な点をさらに掘り下げて。
見落としている細部やニュアンスも。事業アイデアは出さないで。

B. 案を疑う

弱点を先に指摘する。改善案は、指摘のあと。

11.自分たちの案を疑う（①-B）【投影と同じ】
いまの課題仮説: （1〜3行）

次の観点で弱点を指摘して。改善案は、指摘のあと別項で。
- 誰の困りかがぼやけていないか
- 検証できない前提はどれか
12.前提を洗い出す

一般論に見え始めたとき。通用する範囲を先に出す。

この回答が成立するために、暗黙の前提となっている条件や、適用範囲の限界があれば指摘して。
事業アイデアは出さないで。
13.自分の答えにツッコミを入れる

自分たちの仮説に、あえて反論する。

自分の回答に反論するつもりで考えて。間違いや論理の欠陥があれば指摘して。
改善は、指摘のあと。事業アイデアは出さないで。
14.うまくいかないとしたら

仮説を進めたときの穴を先に見る。改善案はまだ出さない。

この課題仮説を進めたとき、うまくいかないとしたらどこか。
リスクを3つ、根拠つきで。改善案と事業アイデアはまだ出さないで。
15.自己採点させる

頼んだことに対して、足りない項目だけ直させる。

先の回答を、頼んだことごとに0〜5点で自己評価して。
足りない項目があれば、そこだけ直して。事業アイデアは足さないで。

C. メタプロンプト／逆質問

成果物ではなく、お願いの仕方をAIに考えさせる。体験は プロンプト18。質問は2問で止めてよい。

16.メタプロンプト（①-C）【投影と同じ】

型は 「～するためのプロンプトを作って」。投影の文は、課題の解像度を上げるとき。

課題の解像度を上げるためのプロンプトを作って。

目的を差し替えるとき:

（やりたいこと）するためのプロンプトを作って。
17.逆質問（①-C）【投影と同じ】

仕様の穴を埋める。AIから人間に質問させる。

タスクの完成度を高めるために、ユーザーに聞くべきことがあれば質問して。
1問ずつ待って。
18.決める問いを先に聞く（①-C）【投影と同じ・体験はこれ】

事業案の前に、次の30分で決める順を出させる。

今の議論を、事業アイデアに落とす前に、課題の解像度を上げたい。
次の30分で決めるべき問いを、重要な順に5つ質問して。
1問ずつ待って。私たちが答えたら次の問いに進んで。
19.お願い文を書き直させる（①-C）

作ったプロンプトは、まだ実行させない。

今のお願い文を、課題の解像度を上げる用に書き直して。
タスクと条件を明確に。そのプロンプトはまだ実行しないで。
事業アイデアは入れないで。

課題を口に出す

①のあとに、仲間へ30秒で言えるか確認する。言えてから②へ。

20.自分の言葉にする
この課題仮説を、チームの仲間に30秒で説明するなら、どう言う？
私の言葉で言い直せるように、短い原稿を1つ出して。
専門用語は使わない。事業アイデアは入れない。

② 成果物をまとめる

順番は 調べごと・壁打ち → 骨子 → スライド。ChatGPT の Chat / Work を想定する。生の議論メモのままスライドにしない。1日目の朝からきれいなスライドは頼まない。

21.根拠を出す

事実が薄いとき。ないものは「ない」でよい。

今の説明を支持する数値や調査結果があれば出して。出典も。
ないものは「ない」と書いて。まだ事業案は出さないで。
22.Chat / Work で調べる・壁打ち
これまでの議論:
（ここにメモや発言を貼る）

お願い:
このお題について調べて。Deep Research が使えれば使って。
まだ事業案は出さない。事実と出典を先に。
調べたあとに、アイディアの壁打ちをして。切り口と問いを出す。
23.Work で骨子を作る
上までの調べごとと議論を前提に、Work で最終プレゼンの骨子だけ作って。
スライドはまだ作らない。
- 枚の順
- 各枚で言うこと（1枚1メッセージ）
- 課題 / 論理 / 伝えたいこと
足りない前提があれば、先に質問して。1問ずつ待って。
24.Work でスライドを作る

骨子が口で言えてから使う。

上で固めた骨子で、Work のスライドにして。
骨子の中身は変えずに、見た目だけ整えて。
1枚に文字を詰めすぎない。発表用。
（応用）プロジェクトで共有する

チームの調べごとやチャットを、プロジェクトにまとめる。コンテキストを共有できる。設定の手順は、このセッションではやらない。

詰まったとき

    今のを半分の長さにして。今ほしい一段だけ
  • 浅い・一般論

    プロンプト10 一段深く聞く、または プロンプト12 前提を洗い出す

  • 事業案ばかり
    新しい事業アイデアはまだ出さないで。課題の切り口だけ
  • 一発で終わった

    プロンプト2 に続けて、プロンプト15 自己採点

  • 何を頼むかわからない

    プロンプト16 メタプロンプト、または プロンプト17 逆質問、または プロンプト18 決める問いを先に聞く

  • スライドを作り始めた
    見た目はまだ。骨子（課題と論理）だけ言って
